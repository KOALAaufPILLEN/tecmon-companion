Regeln zum Festhalten

Entwurf für AGENTS.md und README

Diese Regeln kommen erst beim Umbau in die Repos. Bis dahin sind sie hier nur ein Vorschlag.

  1. Ein Menübaum. Alle Einstiege (Rechtsklick, Tray, Linksklick-Fenster klein und groß, Companion-Seite im Browser) lesen dieselbe Liste MENU_AREAS: Start, Spiele, Videos, Overlays, TecMon, Einstellungen. Die Reihenfolge ist fest. Neue Funktionen kommen genau in einen Bereich.
  2. Schnellmenü = sechs Zeilen. Je Bereich höchstens eine direkte Aktion, gleich in Einfach und Erweitert. Ein Klick auf den Namen öffnet diesen Bereich im Fenster. Das Tray-Symbol zeigt dasselbe Schnellmenü. Das alte Windows-Listenmenü „Alle Optionen“ entfällt.
  3. Einfach/Erweitert sortiert nie um. „Erweitert“ hängt nur Zeilen unter „Für Fortgeschrittene“ ans Ende eines Bereichs. Fehlermeldungen sind in beiden Ansichten sichtbar.
  4. Titel sind Namen, keine Zustände. Eine Zeile heißt „Clip-Puffer“, nicht „Clip-Puffer ist aus“. Der Zustand steht rechts als kurzes Wort („an“/„aus“) oder als Raute.
  5. Ein Bauteil je Aufgabe. Zeile, eckiger Schalter, Auswahl, Knopf und aufklappbare Unterkarte. Keine Pillen-Schalter, keine Windows-Häkchen, keine Checkboxen für An/Aus. Gold heißt „aktiv“, Lila ist der Rahmen, Rot ist nur für Gefährliches.
  6. Gefährliches steht unten. „Paket entfernen“, „Figur ausblenden“ und „Companion beenden“ stehen am Ende ihres Bereichs, nie mitten in einer Liste.
  7. Ein Wort, eine Bedeutung. „Spiele“ meint nur unterstützte Spiele. TecMons Spiele heißen „Minispiele“. „Videos“ umfasst Highlights und Clips. „Einstellungen“ meint den ganzen Bereich, nicht nur die Figur.
Umsetzung später

So käme es in den Code

1. Menübaum als DatenMENU_AREAS in public/menu.js ersetzt die heutigen sieben Gruppen. /api/state liefert dem C#-Teil dieselbe Liste.
2. Schnellmenü neuBuildQuick() zeichnet sechs Bereichszeilen. Der Tray zeigt QuickMenu statt ContextMenuStrip. Der eckige Schalter ersetzt die Pille.
3. KartentitelDie h2 der Karten bekommen feste Namen, der Zustand kommt in ein Abzeichen. Alle Sprungziele (Jump(), Hash-Links) bleiben gültig.
4. PrüfenDer bestehende Navigationstest wird auf sechs Bereiche erweitert. Ein neuer Test prüft, dass jedes Bedienelement aus dem Inventar genau einmal erreichbar ist.
